## How to run things

- **Unit tests:** `pnpm typecheck`, `pnpm lint`, `pnpm test`. A few tests time out at 5 s when the CPU is busy (`fetch.test.ts`, `light-grid.test.ts`, `sky.test.ts`, `bench-lock.test.ts`). They pass when run alone, so re-run a failing file alone before believing it.
- **GPU pages:** `pnpm test:gpu --gpu nvidia --filter <page>`, wrapped in `node tools/reference/bench-lock.ts run --no-cool-wait --what "<label>" -- <cmd>`, so runs from parallel agents don't collide.
- **The lock:** it's a folder in the temp directory. `node tools/reference/bench-lock.ts status` says who holds it. Never remove a lock someone else holds. One stale, ownerless lock was removed on 2026-11-09, after checking that no native or lock-taking process was running and that M4 didn't own it.
- **Worktrees:** `git worktree add -b m3-tX.Y ../webgpu-ddgi-m3-tXY m3`. Link the git-ignored data (assets/downloads, assets/generated, bench/references) into each worktree. On Windows that was junctions. On the Mac, use `ln -s`; Git Bash's `ln -s` on Windows copies whole folders, so don't use it there. Then run `pnpm install --frozen-lockfile`.
- **The wind tree** is generated, not downloaded: `node tools/assets/fetch.ts --only wind-tree` re-creates it, and its sha256 is checked.
- **Bistro** loads with compressed textures by default (gputex BC7/BC5, T3.12). On `m34`, M4 switches the viewer to `all-compressed`.
