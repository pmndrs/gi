## For Dennis to review: M4 contract additions

All optional and backward compatible. `docs/api/platform.md`, "During M4", lists them.
- Host-facing:
  - `CompressedPixelData` as a `TextureSource`;
  - `MaterialDescriptor.metalness`, `metalnessTexture: { texture, channel, uv? }`, `opacity`, `alphaMode: 'opaque' | 'cutout' | 'stochastic'`;
  - `requiredLimits` asks for `maxTextureArrayLayers`, and `optionalFeatures` for texture compression;
  - `stats.memory.textures`.
- Technique-facing: `giSurfaceAtCone`, `RayQueries.capabilities.alphaCutouts`, and **`capabilities.perTriangleMaterials`** (new, not in the design's list).
- Implementation-facing for now: **`HitShadingSettings.sampleTextures`**. Hosts can't reach it through `GIPlatform`. The viewer reaches it through `GIPlatformImpl.shade.settings`. Exposing it is Dennis's call.
- three adapter rulings beyond the design: `alphaHash` is stochastic, `ShadowMaterial` lets light through, `giAlbedo` replaces `color` only, custom shading drops `map` unless `giAlbedoMap` is set, and the `flipY` v-flip. All in DECISIONS 2026-11-09.

## Review notes not yet fixed, and known issues

- **Intel `DXGI_ERROR_DEVICE_HUNG`:** `trace-materials` hangs the Intel UHD when it runs third in a batch, and passes alone. Run it alone on the Intel. This is the T3.19 batch-hang pattern.
- **Textures arriving late:** a same-device `GPUTexture` source arrives 1–2 frames late, because it is checked first. A destroyed one isn't caught; the contract says to keep it alive until its layer is built.
- **The albedo debug view** adds 1 to `stats.recompiles` when it's first shown. Accepted; the tooltip says why.
- **The hello example** (`examples/webgpu/hello/scene.ts`) still passes only material slot 0 and no textures.
- **Later** (DECISIONS): vertex colours, `alphaMap`, tinted glass, coverage-preserving alpha mips, a BC7 GI store.
- **Unreliable timings:** these were taken while Cycles was rendering on the CPU. The Bistro viewer frame (p50 98 ms against T3.12's 44 ms) and the `updateMatrixWorld` hooks (600 ns a mesh against T3.0's 50) need a re-time on a quiet machine.

## Running it

Everything runs from a clone at the branch, after `pnpm i`.
- **Unit tests, lint, types:** `pnpm lint && pnpm typecheck && pnpm test`. Some tool tests time out at 5 s under CPU load and pass alone (T3.19).
- **GPU pages:** `pnpm test:gpu --gpu nvidia|intel --filter <pages>`. On the Mac, leave out `--gpu` (`pnpm test:gpu --help`). M4's pages:
  - `trace-materials`, `ddgi-alpha-wall`, `m4-see-through-walls`, `ddgi-glass-pane`;
  - `ddgi-textured-furnace`, `textures-uv-board`, `textures-sources`;
  - `three-m4-textured-furnace`, `three-m4-glass-mesh`, `three-m4-compressed`, `three-m4-flip-y`, `three-m4-viewer-gi-only`;
  - on `m4-t4.5`: `m4-textured-accuracy` (run through its `run.ts`; see its file header);
  - also `ddgi-leak`, and on `m34` `viewer-textures` (`VITE_DDGI_SCENE=bistro-exterior`) and `three-change-tracking`.
- **Viewer, on `m34`:** `pnpm dev`, then the printed URL with `?scene=` set to one of:
  - `bistro-exterior`, `bistro-interior`;
  - `sponza-full`, `sponza`, `furnished-room`, `courtyard-tree`;
  - `textured-furnace`, `uv-board`, `alpha-checker`, `glass-wall`.

  `&gitextures=0` turns GI's textures off; GI then reads each texture's mean colour. The debug menu has "GI albedo at hits". Compare uses the textured Cycles references when they're present.
- **Models** come from `pnpm assets:fetch` into `assets/downloads/` (git-ignored). The worktrees here linked it as a junction to one shared copy.
